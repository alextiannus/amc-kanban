# Kanban / Content 权限总览

状态：本地实现与验证；未部署、未以生产账号验证。规则版本 `2026-09-17.1`，接口协议版本 `1`。

## 使用方式

管理员打开 **用户与权限管理 → 权限总览**。角色矩阵支持五角色对照、搜索、仅看可用和仅看冲突；点击状态查看菜单、入口、操作、范围及来源。账号管理的“查看权限”自动带入账号；用户组详情的“查看权限”自动筛选角色。

账号诊断每次重新读取数据库；选择品牌后调用原有 `canAccessBrand`。它不会代登录、签发用户凭证、执行业务请求或修改授权。菜单由当前组合的真实 `getMenuGroups` 计算，不能简单合并五列。

## 已确认的规则差异与限制

1. 研究员可见 Kanban AI 角色库菜单，但 `/admin/content-lab` 拒绝；旧 `/admin/ai-roles` 反而允许管理员和研究员，不能把它当同权限别名。旧入口签名也不绕过 Content API 限制。
2. 研究员与品牌主或 BD 组合时，不再走“纯研究员”菜单分支；入口权限与菜单显示可能不同。
3. 工作日志菜单只对管理员显示，而视图权限函数允许主理人和品牌主；账号快照的实际渲染检查复用了数据分析权限，与菜单不一致。
4. 无角色账号的旧 `BRAND_DIRECTOR` 回退会被 Sidebar 解释为主理人菜单；服务端仍然没有该角色。诊断展示此差异，不修改它。
5. 部分服务端认证会合并关联账号的角色，而菜单角色来自账号本身；账号诊断分别列出角色及来源。
6. 主理人视频生产需授权品牌并携带该品牌进入 Content；从其他内容入口获得的凭证不一定带品牌。现存 Content 浏览器凭证、过期时间和撤权同步不由此功能验证。
7. `loginLabUser` 辅助函数只允许 ADMIN，但当前 HTTP 服务没有挂载直接登录路由。因此直接登录标为“未核实”，没有虚构 `/admin/login` 地址。
8. Capability 允许不代表所有对象操作会成功。品牌、订阅、对象状态、额度、模型、第三方服务及具体接口仍可能限制操作；尚未逐项核对的模块操作标“未核实”，不作为放行依据。

上述差异只做诊断，不改变业务权限，也不新增动态 RBAC 配置。

## 只读接口

| 接口 | 认证 | 返回 |
|---|---|---|
| `GET /api/admin/access-overview` | 有效管理员网页会话 | 五角色矩阵、两个服务规则版本、查询时间、冲突清单 |
| `GET /api/admin/users/[id]/access-overview?brandId=...` | 有效管理员网页会话 | 账号状态、菜单/服务端角色、授权品牌及来源、所选品牌计算结果 |
| Content `GET /v1/internal/access-overview` | `x-content-service-token`，现有内部服务认证 | Content 五角色描述；不是用户登录接口 |

Kanban 使用 `AMC_CONTENT_SERVICE_URL` 和 `CONTENT_SERVICE_INTERNAL_TOKEN` 连接 Content；不从浏览器传递角色或内部令牌。所有响应 `Cache-Control: no-store`。无有效网页会话（包括仅携带 API Key）`401`，已登录的非管理员 `403`，目标账号不存在 `404`，本地读取失败 `500`。Content 内部接口只接受 GET，其余方法 `405`。

响应目录条目包含 `id/system/group/label/href/aliases/menu/page/operations/scope/status/sources/notes`；每层结果含 `state/reason`。状态为 `allowed/denied/conditional/comingSoon/conflict/unknown/na`，分别显示允许、禁止、需满足条件、待开放、规则冲突、未核实、不适用。账号结果不包含密码、API Key、登录令牌。

Content 超时（5 秒）、认证失败、版本或结构不匹配时，仅 Content 部分显示“未核实”。不回退为旧规则，不影响 Kanban 结果。修改描述规则时应同步更新两端规则版本并验证协议。

## 验证与上线验收

- 两仓库运行 `npm run test:access-overview`；Kanban 另运行 `npm run typecheck`，Content 运行 `npx tsc --noEmit`。
- 测试覆盖全部 32 种角色组合与实际菜单对照、品牌上下文、撤销授权、停用账号、无角色回退、管理员会话限定、Content 真实 HTTP 内部认证及只读契约。
- 浏览器组件验证使用合成账号，覆盖角色/账号入口、品牌切换、详情、冲突/空结果、移动端、Content 离线及错误重试。合成数据验证不替代生产验收。
- 部署先更新 Content 再更新 Kanban；无数据库迁移。任一服务版本未匹配期间 Content 显示未核实。
- 生产验收记录两个部署 SHA、协议/规则版本、代表管理员/主理人/研究员账号、品牌、验证时间和结果。当前未执行生产验收，不宣称线上权限问题已修复。
