# AMCMM 品牌策划共创工作区

本文描述当前三步流程。每次生产发布以独立验证记录中的提交、部署状态及在线行为为准。

## 三步流程

1. **AI Insight**：只展示最新已完成报告。统一比较本品牌已保存摸底报告、Growth 当前 V3 报告及 `BrandMarketingSolution.kind=MANAGEMENT_REPORT` 的完成版本；按分析周期结束时间、完成时间和稳定 ID 排序，日期缺失不能当作最新。只读取真实产物，不把原管理报告页面的演示数据当成真实月报。Growth 读取失败保留已存报告，标明来源状态；无任何可读来源且上游不可读时提示读取问题。
2. **品牌访谈**：AMC Skill 综合最新报告、现有品牌资料、最新访谈和附件，按“当前信息 → 希望补充的信息”展示可编辑品牌定位，区分来源、时间、用户确认和待确认；支持直接编辑、对话和上传资料。只有三个来源变化时才更新受影响部分，不设置准备调研文档步骤。
3. **品牌营销策略**：基于现有资料和可用品牌定位（可缺失、为草稿或已确认）生成策略草案，营销方向与卖点在本步完成，不设置独立方向确认。默认展示最终结果与“期望补充信息”；正文按品牌定位、客户与客流、竞品、获客转化、AMC工作、Content Strategy、店内运营七章组织；自然年度活动日历及至少提前两个月的策划、连续六个月计划作为附件。来源详情与编辑区按需展开。

独立季度导航移除；旧 `focus`、`selling_points`、`annual` 和 `quarter` 契约及原数据保留，季度和内容日历不自动重建。已有年度/季度策划通过第三步详情对照。

## 报告申请

无报告时显示「品牌报告尚未完成」与「Request an AI Insight Report」。点击后服务端预留申请 ID，以稳定 provider idempotency key 创建 Growth 任务。丢失回执保留原申请，重试同一 key；处理中的重复申请返回原 ID。申请成功显示「已申请，报告完成后将在此展示」。需要证据复核、失败及服务不可读分别展示，不能把申请成功当作报告完成。

| API | 作用 |
| --- | --- |
| `GET /api/brands/:id/insight/sources?reportVersion=:id` | 读取项目隔离的数据源、可编辑权限、指定报告输入快照与更新提示 |
| `PUT /api/brands/:id/insight/sources` | 按 expectedRevision 保存来源及移除范围，附件必须属于本品牌；版本冲突保留编辑，重复保存可恢复回执 |
| `GET /api/brands/:id/insight` | 读取统一最新报告、来源状态和真实申请状态；有写权限时核对并同步已完成原任务，不启动新调研 |
| `GET /api/brands/:id/insight/pdf?version=:version[&download=1]` | 校验品牌权限和当前报告版本，返回原始 PDF；预览 inline，下载 attachment；版本更新返回 409，缺失 404，读取异常 502 |
| `GET /api/brands/:id/interview-information` | 核对三个来源的版本；不创建模型任务 |
| `POST /api/brands/:id/interview-information` | 通过当前 AMC Skill 整理品牌定位；同来源复用原 IAIC 任务，来源冲突 409，记录来源审计；失败可显式重试 |
| `POST /api/brands/:id/insight` | 显式申请或恢复原申请，返回真实申请 ID |
| `POST /api/brands/:id/ai/tasks/:taskId/planning` | 从原持久任务读取并保存经过验证的候选，不接受浏览器伪造的 AI 产物 |
| `POST /api/brands/:id/planning-document` | 保存文档或显式确认，提交 stage/action/content/attachmentIds/expectedRevision/requestKey；principal_strategy 为单独主理人策略输入，访谈结果兼容 interview 键但语义为品牌定位 |
| `POST /api/brands/:id/planning-document/attachments` | multipart `file`，保存本品牌附件及实际解析状态 |

## 文档、确认与附件

保存草稿和确认都是可选操作，可直接确认当前编辑内容，无需先单独保存。服务端记录确认人、时间和输入版本，使用品牌行锁、工作区 revision、审计和幂等回执；冲突保留浏览器草稿。所有步骤可独立进入或跳过，报告、访谈、定位确认和主理人输入均不构成生成前置条件。缺失与未确认信息只作补充提示；旧方向确认仅作历史兼容。长文压缩后的摘录不能代替服务端完整资料计算的 `confirmationState`。

附件支持 TXT、Markdown、PDF、JPG、PNG、WebP，单个不超过 10MB，每份访谈最多 20 个引用。使用 OBS 存储，文字提取后仍标为待确认；图片复用现有分析队列，未配置或未完成分析时保留待核对状态。PDF 原件可以提交，当前未提供 PDF 自动文字提取，需用户补充重点信息。解析不成功不丢附件，也不声称 AI 已读懂。

品牌定位或主理人输入变化后，保留既有方案并提示复核；用户仍可生成、编辑和保存其他步骤。新版本记录本次使用的输入版本与确认状态。完整方案的人工编辑文档为当前内容，`structuredDataStale` 表示原结构化生成字段只供对照。正式确认另存 `BrandMarketingSolution` 版本。草案记录真实生成任务加载的 Skill 内容哈希及报告引用，不能用采用时的新 Skill 冒充生成时版本。

## 界面与权限

桌面阶段导航、文档和对话分栏；手机采用阶段切换和文档/对话双视图。AI Insight 隐藏通用讨论、草案及起始月份操作。键盘打开时精简导航，保持输入和发送可见。品牌切换隔离报告、对话、候选、编辑草稿和在途回执。新写接口在 MM 代理和业务端均检查适用的来源及品牌写权限，multipart 保持原始二进制。

## 验证入口

- `scripts/test-brand-planning-v2.mts`：最新报告排序、必需章节、跨年六个月及旧数据保留。
- `scripts/test-latest-insight.mts`：真实隔离数据库月报、摸底及 Growth fixture 的统一选择和离线回退。
- `scripts/test-insight-request.mts`：持久申请、未知结果恢复、provider key 和重复请求。
- `scripts/test-planning-document.mts`：保存/确认、长文确认状态、附件隔离、完整方案及版本历史。
- `scripts/test-planning-workspace.mts`：旧年度/季度、冲突和并发幂等。
- `scripts/test-brand-planning.mts`：真实 IAIC 运行时，含合并方向及完整策划，模型/Growth 使用 fixture。
- MM `scripts/test-planning-workspace-v2-ui.mjs`：实际组件、四种屏宽、键盘视区、申请、文档和确认。
- MM `scripts/test-planning-proxy.mts`：跨站写拒绝及二进制附件代理。

真实中央模型和 OBS/Growth 的登录后线上联调、发布及 live 健康标记不属于这些 fixture 测试的证明范围。


报告及访谈当前实现（2026-10-18，本地验证通过）：AI Insight 从当前品牌关联的 AMC Growth 同步最新已产出的报告版本，读取该版本正文与 PDF 路径；页面预览与下载同一版本 PDF，不将内部 JSON 字段直接展示为正文。读取失败保留已同步资料并标记同步状态，不把错误当作文件缺失。品牌访谈通过 AMC 营销策略 Skill 统一整理当前品牌定位，下方列出希望补充的信息；去掉准备调研文档操作。已确认资料不会被自动覆盖。

Growth 同步读取品牌报告版本列表与版本详情的 `report_content`、`result.pdf_download_path` 等字段，不再把 `download-json` 原始数据递归转成正文。同步快照与用户确认资料分开；内容未变的轮询不更新快照时间。支持 Growth 返回的 `/public/downloads/brand-intelligence-intake/...pdf` 与 `/downloads/...pdf` 格式。PDF 通过本品牌授权接口读取原始字节；预览与下载共用同一 Blob。访谈仅列来源明确的补充项，已有答案不重复询问；无明确缺口时允许直接补充近期变化。

访谈信息整理当前实现（2026-10-18，本地验证通过）：由 AMC 营销策略 Skill 统一整理最新 AI Insight、现有品牌资料和最新访谈/补充记录，输出“当前信息 → 希望补充的信息”。只按报告、品牌资料和最新访谈三个来源的版本复用真实 IAIC 任务；其中任一变化才更新品牌定位受影响的部分，保留其他已确认内容。每次实际整理使用当前 Skill；Skill/月份/语言变化本身不触发重写。保存和确认仍为用户操作，AI 整理不得自动覆盖用户资料。来源发生变化时不得采用旧整理结果。

品牌访谈的产出为品牌定位（兼容 coCreation.interview 存储）。完整营销策略必须绑定已确认品牌定位、真实当地节假日与节点、主理人策略输入，并依据社交平台默认定位规划内容类型和活动节奏；Subscription 暂不作为策略输入，不规定各平台具体发布次数；不可读和缺失保留待确认。主理人策略输入另行编辑，不触发品牌定位更新；方案输入版本随之失效重审，旧定位不被反复改写。


Skill 分步交付规范（2026-10-18，规则文本更新，尚未验证本次生产部署）：三步均规定 Input、必须完成动作、Output 内容与格式、完成条件；正式文档使用可编辑 Markdown，宿主结构化输出仍严格遵守原 schema。品牌定位须包含商家忌讳词汇、禁用说法、适用范围、替代表达及来源/确认状态，未提供列为待补充；后续方向、卖点和策略继承表达边界。完整策略须包含当地节庆及日期来源，每项拟执行节庆活动至少提前两个日历月启动策划，并给出里程碑；期限已错过标明准备期不足及调整建议。按活动列明门店配合动作、商家/销售/主理人/AMC AI责任角色、截止日、资源、验收及确认状态。全年12个月与滚动连续六个月均保留；Subscription和平台具体发布次数仍不作为策略输入。规则不等于模型输出已通过生产验证。


当前维护源：`packages/amc-skills/skills/amc-marketing-expert`。旧 direction/focus/selling_points 保留历史兼容，不是当前策略的独立必需输入，也不自动代替主理人策略输入。结构化 marketing_plan 增加可选 strategyDirection 与 informationToSupplement 字段，旧方案仍可读；完整可编辑文档含方向、七类策略内容及期望补充信息。正式策略只绑定当前已确认品牌定位与主理人输入；比对历史 inputVersions 时忽略已停用的 direction 字段，其他版本检查保留。

## AI Insight 数据源管理

来源清单在报告下默认折叠，支持链接、品牌资料、文件或图片的添加、修改与移除。来源名称、采集/未验证状态和当前报告输入可直接对照；报告来源快照单独展开，只读保留历史依据。当前配置、排除规则共同构成 revision；每次变更保留不可变版本记录。移除不删除原始资产或历史报告，也不得通过后续自动发现将已排除来源重新当作商家事实。

Growth 以 `amc-kanban-<brandId>` 作为私有来源作用域，不能仅按品牌名称合并私有资料。Kanban 根据已授权项目绑定作用域、操作者和附件真实 URL，不接受浏览器替换附件地址或跨品牌引用。来源接口只允许内部服务凭证；带项目来源的报告使用独立私有产物命名空间，限制通用路径和任务读取，不进入公开品牌目录。原公共摸底报告继续保留原路径。

`POST insight` 的显式更新接受 `refresh=true`、`sourceRevision`、`previousRequestId`。以实际来源版本和上一申请 ID 绑定新申请，重复点击或丢失回执不重复创建报告；处理中的申请可查询恢复，未完成不冒充报告。来源修改后仅提示“数据源已更新，报告待重新分析”，不会自动发起分析，也不会自动覆盖品牌定位。

来源上传复用品牌附件存储，提交 `purpose=insight_source` 时不在上传路径触发图片分析。TXT/Markdown 提供有界文字摘录，PDF 和图片未读取内容明确待核对，可加说明；仍可生成带缺失提示的报告或策略。

## 非阻断工作流与中断恢复

报告缺失、访谈尚未完成、定位未确认、主理人输入为空、自动整理失败，都不会禁用其他步骤或阻止交付可用策略草案。未知与冲突统一写入期望补充信息，既有信息和浏览器未保存编辑保留。

同来源的自动整理任务默认复用，只有来源更新或用户显式重试才新建。显式重试只允许已停止任务；确认历史调用仅为已结束的资料读取和内部草稿写入后，通过原 Core 取消/创建接口建立新任务，保留旧用量记录、工作区和来源审计。运行中、等待外部结果或存在未知业务操作的任务不会自动重复执行；这一状态不影响人工编辑或其他步骤。未改动 Core 或人工清除用量账本。

| 用户流程审计 | 页面行为 | 验证 |
| --- | --- | --- |
| 查看来源与当前报告快照 | 默认折叠，展开查看完整详情及验证状态 | 320/390/768/1440 UI 回归 |
| 添加/编辑/移除来源 | 显式保存、来源版本冲突保留草稿，历史报告不变 | PostgreSQL 来源版本、移除规则及保存重放 |
| 上传来源文件或图片 | 品牌隔离、真实资产 URL、上传不触发分析，内容未知明确提示 | 附件所有权与上传目的回归 |
| 按来源更新报告 | 提示待重新分析，显式申请且重放恢复相同回执 | 来源版本绑定、重复申请及真实 HTTP 权限测试 |
| 跳过报告及访谈直接生成策略 | 三步独立，无定位确认前置条件 | UI 直接生成与空工作区保存/确认 |
| 整理失败继续使用 | 保留现有信息和编辑，仍可进入策略；安全显式新任务重试 | 中断恢复调用边界、来源作用域与新任务回归 |


### 第四步：执行清单
所有阶段可独立进入。根据现有策略生成结构化执行清单，每项仅展示具体行动、计划时间和完成 checkbox；店内配合也是普通任务。AI 新增任务默认未完成，用户勾选／取消勾选经品牌写权限、Origin 和版本校验后保存并审计。重新生成复用任务 id，保留完成记录和旧任务。缺失资料仅列期望补充信息。营销策略按月提出团购、新品促销、节庆促销等适用活动并标记真实确认情况；待商家确认不构成前置关卡。


### 品牌策划性能修复（2026-11-01，实施中，生产状态以验收记录为准）
品牌策划的首次上下文读取和成功工作区写入后的完成回执由宿主提交，仍经过同一 Runtime 授权、审计与独立完成验证。品牌策划固定的必读 amc-marketing-expert 由宿主在上下文成功返回后调用同一 Skill 读取工具，避免模型仅为选择已确定的技能再消耗一轮完整上下文。失败读取、新用户输入及非固定技能交回模型；额外研究、策略判断及校验失败后的修正继续由模型处理。已保存完整策略正文在模型输入中只携带一次，结构化旧字段只在缺少完整正文时补充；不改变持久化历史和人工编辑。有效的对话来源缓存先按当前来源 revision 无锁读取，缓存缺失才进入原事务锁，保留跨进程合并、来源变化和权限校验。模型不因性能优化自动降级，线上效果需以真实调用次数、耗时及保存回执核验。

新生成的营销策略以 strategySections 七章正文为主，保留年度和六个月计划为附件，移除同一新产物内的旧版摘要/SWOT/卖点/创意重复字段。旧结构化方案仍可验证与读取，不迁移或覆盖历史。首次与后续对话均从经过原任务验证的不可变产物读取并执行幂等保存，避免首次对话误走实时上下文重建；仍核验当前品牌权限、原任务归属及保存 revision。
