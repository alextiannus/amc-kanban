# AI Marketing Crew daily publishing

Scope: only AI Marketing Crew, explicitly authorized by its active human principal with platform administrator permission. The user selected Instagram `alextiannus` and Facebook `Wormwood Pte. Ltd`, one photo post per account per Singapore day, seven days ahead. Default slot18:30SGT, excluding slots less than30minutes away. TikTok remains outside this photo-post policy.

The worker selects diverse sources from AMC Academy articles/courses/cases, recorded genuinely published posts with public URLs, and ready image assets across AMC brands. Candidate reads are bounded (200articles,300published posts,500images); this is a discovery window across all brands, not a complete export. Previously used source revisions are excluded from the recent200 slot history. Private drafts, denied/revoked/expired/restricted media and uncaptioned images are excluded. Unknown rights are explicitly subject to human review. An available database record is not a claim that AMC owns the merchant's media or results.

Existing Content generation uses the active encrypted database-backed model policy. Academy/publication insights become standalone caption plus deterministic1080×1350PNG marketing card stored in OBS. Image sources on the configured OBS origin are safely downloaded with redirect/byte/pixel limits, fitted without cropping into1080×1350PNG, and receive new captions and target-brand assets. External-origin image records are text-only references for an original marketing card, not arbitrary server downloads; the original source/version remains linked and is rechecked. Do not claim customer collaboration, performance results, offers, prices or personal experience from an unrelated merchant example. Sources are untrusted data, never authority. Native Core Token reporting currently does not cover this existing Content-generation path; monetary costs remain unknown without verified rates.

`amc_iaic.daily_publishing_policy` stores enabled/owner/accounts/revision. `daily_publishing_slots` stores one immutable account/local-day identity, planned time, source revision and original draft. A session-level advisory lock serializes refills across instances. Store `generating` before any model call; uncertain calls never automatically repeat. Interrupted calls become needs_attention after20minutes. A missing source/persistence response requires inspection of the original slot/draft/provider log. Disabling/revising the policy or revoking source rights blocks subsequent delivery. Already accepted provider schedules require explicit provider reconciliation; disabling policy is not a promise to recall remote posts.

New stock is **unapproved**. `/daily-publishing` shows provenance, image, caption, account and exact schedule. An active authorized browser session must check the explicit rights/content/account/time approval; personal API keys and assistant tools cannot approve. Content/asset/account/time mutations invalidate the approval. Approved content enters the existing durable delivery queue, then provider scheduling, then polling for actual publication. Queue/scheduled state is not proof of published content. Expired slots never silently move to a new time; human approval must be renewed through the normal draft workflow.

The background worker checks every5minutes, attempts at most3new drafts per scan, reports attempted calls separately from actually saved drafts, and stops on shutdown. Self-addressed station notices deduplicate shortages/failures per owner/account/day, with a separate overdue notice for schedules lacking confirmed publication after1hour. `RESULT_UNKNOWN` is preserved for original-request reconciliation, never automatically recreated. Availability of approved stock depends on the owner's review; no daily scheduler can turn unreviewed drafts into authorized posts.

API: GET `/api/brands/:id/daily-publishing` returns sanitized status; POST `configure` requires AMC principal+ADMIN and policy revision, POST `refill` organizes at most3unapproved drafts, POST `approve` requires same-origin human session, exact draft revision and explicit rights confirmation. All responses no-store; status/approval remain available during text-model-policy outages.

Shared native/external assistant tools: `daily_publishing_status`, `daily_publishing_sources`, `daily_publishing_refill`. They use the same scoped service and never approve content. The normal brand catalog/role check still applies. Cross-brand source access is limited to this explicitly authorized internal AMC operation and current administrator owner.

Validation: `node scripts/run-daily-publishing-postgres.mjs` under Node20 runs isolated PostgreSQL fixtures, real services/routes, mock provider creation, source withdrawal after approval, CSRF/version protection, seven-day/concurrent/restart behavior, native tool access, notification dedup and unknown-result handling. Fixtures never publish to real accounts. Production deployment, source stock, human approval and actual platform publication must be verified separately.
