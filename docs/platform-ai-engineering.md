# AMC Platform AI 工程执行契约

## `/BUG` 与 Platform AI 工程维护（2026-10-15，已部署启用，自动修复闭环验收中）

文字对话识别 `/BUG`（大小写无关，可附描述），独立持久上报并立即返回编号；原聊天继续。报告保留用户/品牌、页面、会话和有界对话，实时授权和稳定请求键保护隔离及重试。报告内容是不可信排查线索，不能选择工程身份、仓库、凭据或发布政策。

Platform AI 采用 IAIC Core Platform Team 公共组合，独立 schema/执行器/原生身份和平台用量，不占用 User AI 对话队列。服务器把报告映射为稳定工程任务；模型、配置和凭据仍使用中央数据库管理。工程能力由 AMC 适配：限定仓库源码读取、隔离候选补丁、GitHub Actions 复现与回归、独立模型审查/PeerReviews、受保护的主分支推进和 Render 部署回读。仓库/发布凭据数据库加密保存，不向模型、浏览器或测试代码暴露。近期商户对话留在 AMC；不得写入公开 GitHub issue、提交说明或 CI 日志。

自动修复限定为已授权仓库和普通应用源码/测试/文档，不能修改鉴权、密钥、财务、工程执行器自身、工作流或数据结构。超出工具范围明确等待人工处理。候选必须包含可复现测试：同一测试在固定基线失败，在补丁通过；固定检查和独立审查同一候选版本通过才可推进主分支。主分支已改变则拒绝发布，不 force-push。每个外部写操作持久保存原效果编号，未知结果先查原回执，不能盲目重放。Render 确认相同 commit live 后才显示已发布；模型总结、审查 no_findings 和 CI 通过都不等于上线成功。

UI 显示上报、排队/检查、测试、审查、发布核对、已修复、未确认/非BUG、需要补充、失败/暂停等实际状态。工程日志不直接向商户展示；只回传经过字段筛选的结论和版本。执行器及上报界面已部署启用；实际请求227毫秒返回且幂等/匿名权限检查通过。真实修复闭环验收中发现并正在修复 CI 就绪轮询缺少 taskId 的衔接，不能宣称自动修复闭环已验收。原生只读就绪轮询可从已持久绑定的 report/task 恢复原生身份校验，普通写调用仍要求原任务上下文。验收需要真实模型和实际仓库/CI/部署闭环，并分别记录模拟故障测试与生产证据。


独立代码与测试执行采用固定 GitHub workflow 和不含生产凭据的容器，禁止模型选择 shell 命令。模型提交的是限定路径的文件修改和单独回归测试。部署适配器只接受服务器配置的服务 ID，复用主分支自动部署。未启用配置时报告仍保留 waiting_executor。

## 部署与控制

工程服务密钥通过 scripts/configure-platform-engineering.mts 的一次性 RSA-OAEP 信封交付，服务端再用基础设施加密根加密入库。明文不进入 Render job 命令、日志或仓库。GitHub 连接只在白名单仓库 API 适配器内使用。首次部署没有配置时不启动模型任务。管理员可通过 /api/admin/platform-ai 查询报告并对原 Core 任务执行 resume、provide_input、cancel；没有面向商户的工程管理权限。未知外部效果通过原 branch、workflow run、main commit 查询和 Core TaskStore.resolveCall 核对，不能推测失败后重发。独立审查的未知模型用量不重复请求，转为待核对。

首次落地沿用当前中央模型策略；原生工程推理通过独立 Platform Ledger 计量，独立审查额外保留实际 usage、供应商引用和固定策略版本，不计入 User AI 账户。默认只处理 amc-mm、amc-kanban。外部 Codex 双向任务接管不属于本轮原生工程闭环，仍待后续接入。

本地验证：scripts/test-platform-engineering.mts 使用真实 PostgreSQL/Core 和模拟外部适配器；scripts/test-platform-github.mts 验证非强推、重复效果、错误基线拒绝和部署版本匹配；原文字对话实际组件四种屏宽回归通过。生产验收尚未完成，不能把测试替身当作真实修复发布。
