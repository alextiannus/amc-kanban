# 排期 TOKEN_REVOKED 修复

状态：2026-09-23 已发布生产，版本 `e3b4822416d32e06bc9545fc1c7f8858c902ec97`。

## Root cause

生产日志于 2026-09-23 01:52:37.624 UTC 记录 [PATCH Draft] Re-submit to PostFast failed after reschedule: TOKEN_REVOKED。该字符串在提交接口来自本地 SocialAccount.connectionStatus=DISABLED 时直接返回 disabledReason 的分支。PostFast 官方账号接口定义 TOKEN_REVOKED 为社交账号授权已撤销，与 AMC 登录令牌及 PostFast 工作区 API Key 无关。

旧代码有三处缺陷：

1. 未向供应商实时查询前即被本地旧状态拒绝，因此即使账号已经重新授权，只要同步尚未更新，仍无法排期。
2. 内部 disabledReason 原样返回给用户，没有说明哪个账号、如何恢复。
3. 编辑已排期帖文先删除远端旧帖子，再发现账号不能发布；失败时仍返回 HTTP 200 / ok=true 和过期的草稿对象。

日志证明当时缓存标记为 TOKEN_REVOKED；没有取得账号持有人的授权操作历史，不能断言是改密码、手工撤销还是平台策略导致，也未直接核对该账号当前远端状态。

## 修复

- 实际提交和改期删除前实时解析目标账号状态；使用现有绑定锁同步 connectionStatus/disabledReason。恢复为 CONNECTED 时清除旧失败原因，移除提交入口的缓存硬拦截。
- 已撤销、到期、断连或停用时显示具体账号与品牌设置中的重新连接步骤；账号被封停时要求先在社交平台恢复。
- 改期前检查不通过时不取消旧帖子、不改本地排期；单独取消和保存草稿仍可执行。
- 取消后的重建失败返回错误状态和最新数据库草稿，不误报排期成功。
- 日历警告识别供应商健康状态，不再仅依赖 expiresAt；提供品牌设置链接。

社交授权若仍被平台撤销，必须由账号持有人重新授权，服务不能自动恢复授权。此次修复不重新发布客户草稿、不修改客户排期、不更换任何密钥；无需数据库迁移。
