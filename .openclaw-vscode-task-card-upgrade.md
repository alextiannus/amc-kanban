# VS Code Agent Task: Upgrade Task Cards for Search, Lookup, and Association

You are working in the `amc-kanban` project. Use VS Code's own AI/execution surface to implement a small, shippable upgrade to task cards and board lookup/association UX.

## Context

Recent work:
- Sprint 1 added task metadata fields: `priority`, `estimatedHours`, `deadline`, `tags`.
- Permission work added `npm run verify:permissions` and tightened API responses.
- Alex now wants stronger task cards for easier querying/searching and association.

## Goal

Improve task card discoverability and association without over-scoping.

## Preferred small slice

Implement as much of this small slice as is reasonable:

1. Board-level search box:
   - Search task title, description, materials, tags, assignee nickname/email, and task id.
   - Works together with existing status/priority/agent/overdue filters.
   - Show filtered count or empty state copy that mentions filters/search.

2. Task card lookup helpers:
   - Show a short task id on each card.
   - Add a copy task id or copy task link affordance if simple.
   - Keep UI clean and compact.

3. Related/association affordance:
   - In TaskModal, show tags as clickable/filterable chips if practical.
   - Add a simple "Related" section based on shared tags or same assignee from currently loaded tasks if possible without backend changes.
   - If backend changes are needed, prefer a minimal `relatedTaskIds`/links approach only if it stays small.

4. Validation:
   - Run `npm run build`.
   - Run `npm run verify:permissions` if API behavior is touched.
   - Run `git diff --check`.

5. Git:
   - Commit and push if validation passes.
   - Do not include unrelated untracked docs: `ANALYSIS_SUMMARY.md`, `COMPETITIVE_ANALYSIS.md`, `ROADMAP_v2.md` unless you intentionally need them.

## Constraints

- Keep the implementation small and shippable.
- Preserve current permission behavior.
- Prefer client-side enhancements first unless backend is clearly needed.
- Avoid leaking sensitive fields in any response.
- If blocked, write a clear blocker to `.vscode-agent-blocker.md`.
